# 裁判 Rubric：2406.10292_cto_trial_outcomes（L1，总分 100）

## 判分模型
- 判分模型：Claude / GLM 等 LLM 裁判均可；证据重算由裁判运行提交代码完成。
- 判分输入：`claim.md`、`code/`、`results/`、`report.md` + 冻结数据 `data/`。

## A. 核心结果达成度（60 分）

| 锚 | 论文值（出处） | 判分规则 |
|---|---|---|
| A1 CTORF 全体 F1 | 0.909（Table 1） | 提交从冻结 phase 数据计算的全体 F1 与 0.909 相对差 ≤10% → 满分；≤30% → 半满；>30% → 低分 |
| A2 CTORF 分阶段 F1 | I 0.913 / II 0.878 / III 0.941（Table 1） | 三阶段分别对照，平均相对差 ≤10% → 满分；≤30% → 半满；未报告 → 低分 |
| A3 人工-自动一致性 κ | 0.729（Table 1，全体） | 提交计算的 Cohen's κ 与 0.729 相对差 ≤20% → 满分；≤40% → 半满；未计算 → 低分 |

- 档位折算：每锚 20 分；满分 20 / 半满 10 / 低分 0-5；A 总分 = 三锚之和（上限 60）。

## B. 证据真实性（25 分）

- 提交必须包含 `code/` 与 `results/`；缺失 → B 直接 0。
- 裁判抽查 1-2 个关键数：
  1. **抽查字段 1**：`results/evidence_table.csv` 中 phase=all 的 CTORF F1。
  2. **抽查字段 2**：`results/metrics.json` 中人工-自动匹配样本量（或全体 κ）。
- 裁判从冻结数据运行提交代码（或独立复核脚本）重算：
  - 能重算且一致 → 满分 25；
  - 有 1 个不一致（>1% 相对差）→ 12-20；
  - 无法重算/无代码/抄论文数字 → 0-10。

## C. 方法与报告（15 分）

- C1（5 分）方法合理：阈值/标签口径、指标实现与论文对齐。
- C2（5 分）泄漏与时间：未用未来信息；匹配逻辑清晰。
- C3（5 分）报告：`report.md` 含方法、结果、局限（匹配样本量、失效场景）与结论标签。
