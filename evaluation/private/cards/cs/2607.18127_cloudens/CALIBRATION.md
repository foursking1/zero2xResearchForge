## 关键设计决策与对锚的影响

- **冻结数据为官方 Zenodo 全量 parquet（2.6GB）**：与论文/复现包输入完全一致（39,365x117,448），子集筛选由 agent 按特征名完成；5xx count 特征数（2,406）作为数据事实抽查锚。
- **锚的稳定性**：ClouDens MD NAB（20.94/26.24）在论文 Table IV 与复现包 CSV 中完全一致 → 作为数值锚；GRU 数值在两种来源有差异（Table IV 5.89/10.95 vs CSV 10.76/14.19），故 GRU 仅作方向/上限约束，不单独严格锚定。
- **NAB 对实现细节敏感**（训练随机性、阈值、NAB 窗口定义）→ A1 以方向为主、A2 用 ±33% 带宽；B 重算容差 ±2.0。
- **计算成本**：A3T-GCN 训练约 304s/A100（论文 Fig 8），CPU 上可能数小时 → rubric B 允许降 epoch 轻量验证 ClouDens 方向 + GRU 完整重算；A1/A2 不要求逐点复现论文绝对数值。
- **风险**：GPU 依赖可能阻碍部分 agent → C 维度给足方法合理性分；复现包可复用但禁止抄数（B 直接 <=10）。
- **若 agent 只做 LF**：A1 最高 12、A2 按 LF 锚上限 13 → 总分自然落低档，符合 L1 难度设计（需完成 MD 主 claim 才拿高分）。
